# LaTeXSnipper Office Add-in for macOS

Word and PowerPoint for Mac cannot load VSTO, COM or custom OLE add-ins, so the Mac version is an Office web add-in. Its pages are served by the LaTeXSnipper desktop app, and it reuses the Windows plugin's shared editor (`src/LaTeXSnipper.OfficePlugin.Editor/EditorAssets`) and MathJax typography renderer (`MathJaxTypographyAdapter.js`) without modification.

## Enable

In LaTeXSnipper **Settings → 启动行为 → Office 插件**. On first enable the desktop app:

1. creates a self-signed, non-CA certificate valid only for `localhost` / `127.0.0.1` under `~/Library/Application Support/LaTeXSnipper/office-addin/` and asks macOS to trust it for SSL (Office loads add-in pages only over HTTPS);
2. serves the pages on `https://localhost:28766`;
3. writes `latexsnipper-office-addin.xml` into the `wef` sideload folders of Word and PowerPoint.

Reopen Word or PowerPoint and choose **Home › Add-ins › LaTeXSnipper**. The add-in works only while the desktop app is running. Turning the setting off stops the server and removes only this add-in's manifests; the certificate stays trusted so enabling again does not prompt. To remove the trust as well, run `security remove-trusted-cert` with the certificate above and delete it from the login keychain.

## Features

| Host | Formulas | Commands |
| --- | --- | --- |
| Word | Native OMML equations (default) or SVG pictures; inline and display | Insert, load and update selected, delete, format selected / all |
| PowerPoint | SVG (default) or PNG pictures | Insert (centred), update keeping position and user scale, delete, format to natural size |

Both hosts have the shared editor, the status pane, typography settings with JSON preset import/export, help, and screenshot OCR through the Automation API (the desktop **自动化接口** must be on).

Windows-only: OLE formula objects and double-click editing, MathType conversion, Word numbering and cross-references, document-wide LaTeX parsing. Windows OLE formulas appear as pictures on Mac and cannot be loaded.

## Compatibility

- PowerPoint formulas use the Windows shape-tag schema 3 (`PowerPointFormulaMetadataStore`), so pictures inserted on either platform load on the other. The Mac-only tag `LaTeXSnipperImageFormat` records SVG vs PNG.
- Typography snapshots and the settings / preset JSON match `FormulaTypographyFields` and `TypographySettingsStore` schema 2.
- Word on Mac lays out an equation as a display equation only when it sits directly in its own paragraph, so display formulas are anchored by a hidden bookmark `_LS<id>` in a centred paragraph and inline formulas by a content control tagged `latexsnipper-eq-<id>`. Metadata lives in the add-in's document settings; picture formulas also carry it in their alt text.
- OMML uses the `mathml2omml.xsl` inside `Microsoft Word.app`, the same stylesheet Word uses, with the Windows `OmmlTypographyMapper` rules ported to `src/integration/office_addin/omml.py`.

## Layout

| Path | Role |
| --- | --- |
| `manifest.xml` | Add-in manifest template (`{{BASE_URL}}`, `{{VERSION}}`) |
| `web/*.html` | Task pane / shared runtime, editor, settings and help pages |
| `web/app/` | Host adapters (`word.mjs`, `powerpoint.mjs`), controller, renderer, WebView2 bridge replacements |
| `web/icons/` | Ribbon icons, generated by `tools/generate_icons.py` |
| `tests/` | Node tests for the shared metadata format |
| `../../src/integration/office_addin/` | HTTPS host, certificate, sideloading, font outlines (Qt), OMML, settings, Automation API relay |
| `../../src/ui/controllers/office_addin.py` | Desktop lifecycle and settings toggle |

The server serves only fixed asset roots and same-origin `/api` routes that require the `X-LaTeXSnipper-Office` header; it never grants CORS and never exposes the Automation API token to the pages.

## Tests

```bash
python -m pytest test/test_office_addin_*.py
node --test office_plugin/macos/tests/*.test.mjs
```

Packaged macOS builds copy these files into `application/office_addin` (`scripts/build_application_resources.py`).
